# Contributing

Thanks for helping make day-trading research reproducible. Junior-developer friendly: if anything below is unclear, open an issue and we'll clarify.

## Quick setup

```bash
git clone <your-fork> && cd daytrade-truth-benchmark
pip install -r requirements.txt
PYTHONPATH=src pytest -q
PYTHONPATH=src python -m dtb.benchmark_real --out results/real_benchmark.json
```

Docker: `docker compose up --build benchmark` (16 tests + both benchmarks, hashed outputs).

## What we accept

- Bug fixes with a failing-then-passing test (`tests/test_*.py`)
- Cost-model / data-source improvements with cited 2026-2027 source + audit-log entry in `docs/05-search-audit-log.md`
- Docs fixes (link rot, typos, clearer math)
- New charts in `assets/` only if generated by a committed script (`scripts/`), never hand-drawn

We do **not** accept: live-trading signals, mirror-trading bots, API keys/secrets, or pirated PDFs in `papers/` (links + DOI only).

## Definition of done

- `pytest -q` green (16 tests)
- No secrets (`git diff --cached | grep -iE 'api[_-]?key|token|secret'` clean)
- README/docs updated if behavior changed; demo re-rendered if output changed (`bash scripts/record_demo.sh`, `vhs docs/demo.tape` when available)
- Conventional Commits (`feat:`, `fix:`, `docs:`, `test:`)

## PR process

Fork → branch → PR with description + `Closes #XXX` + testing checklist. One reviewer minimum. CI must pass.

Questions? Open a Discussion or issue — no DMs needed.
